# KELVRIN — Full Production Codebase Audit & Defect Catalog

**Audit Date**: 2026-09-14  
**Auditor**: Senior Full-Stack, AI, Security, and QA Engineering  
**Application**: KELVRIN — Sovereign Agentic AI Workbench  
**Audit Status**: Initial Audit Complete — Remediations Planned

---

## 1. Executive Summary

This comprehensive audit inspects the current state of KELVRIN across the frontend, backend, database, model routing, AI inference, task classification, document processing, file generation, security posture, and test suites.

While the fundamental architecture (React frontend, FastAPI backend, SQLAlchemy ORM, isolated sandbox, deliverable generators, and audit log subsystem) is solidly implemented, several critical production-blocking issues were identified that degrade AI response quality, pollute the UI with test artifacts, violate brand/sovereignty guidelines, and break file-generation workflows.

---

## 2. Catalog of Identified Defects & Root Causes

### Defect 1: Model Dropdown Pollution & Duplicate Model Records
- **Symptom**: In the AI Assistant and Model Center, the model selector contains duplicate entries (e.g., "Direct Override Engine (MOCK)" appearing 21 times, "Mock Failure Node (MOCK)" appearing 23 times, "Super Llama" appearing 29 times).
- **Root Cause**:
  1. Backend tests (`test_phase6_models.py`, `test_phase7_chat.py`) directly executed against the main SQLite database (`kelvrin_sovereign.db`) instead of an isolated test database. Each test run inserted mock model rows with random UUID suffixes.
  2. The endpoint `GET /api/v1/models` in `backend/app/api/v1/models.py` queried all rows from `model_registry` without deduplicating by stable ID or filtering out test/mock entities in production mode.
  3. The frontend (`AiAssistantPage.tsx`) mapped all returned backend rows directly into `<option>` tags without frontend deduplication or filtering.
- **Affected Files**:
  - `backend/app/api/v1/models.py`
  - `backend/app/db/init_db.py`
  - `frontend/src/pages/AiAssistantPage.tsx`
  - `frontend/src/pages/ModelsPage.tsx`
  - `kelvrin_sovereign.db` (181 rows in `model_registry`)

### Defect 2: Generic / Static / Template AI Responses
- **Symptom**: Different user questions receive similar, static, or repetitive template responses (e.g. `"Sovereign response generated by local model '...' via provider 'mock'..."`).
- **Root Cause**:
  1. `backend/app/services/model_provider/mock_provider.py` lines 84–116 contained static hardcoded templates when local vLLM/Ollama servers were offline or when mock providers were selected.
  2. The chat message pipeline in `backend/app/api/v1/chat.py` only invoked `model_router.route_and_execute`, which defaulted to the mock provider upon connection failure, emitting static text without evaluating the user's specific prompt.
- **Affected Files**:
  - `backend/app/services/model_provider/mock_provider.py`
  - `backend/app/services/model_provider/factory.py`
  - `backend/app/services/model_router.py`
  - `backend/app/api/v1/chat.py`

### Defect 3: Task Classifier Lacks Enterprise Task Types & Deliverable Detection
- **Symptom**: Task classifier only mapped prompts to 6 low-level capabilities (`TEXT`, `REASONING`, `CODING`, `VISION`, `OCR`, `EMBEDDING`). It did not recognize distinct enterprise task types such as `GENERAL_QA`, `DOCUMENT_SUMMARY`, `DOCUMENT_QA`, `KNOWLEDGE_SEARCH`, `DATA_ANALYSIS`, `CALCULATION`, or `FILE_GENERATION`.
- **Root Cause**: `backend/app/services/task_classifier.py` was built around regex capability matching rather than structured intent detection with deliverable triggers (`target_file_type`, `requires_tool`, `requires_document`).
- **Affected Files**:
  - `backend/app/services/task_classifier.py`
  - `backend/app/schemas/model.py`

### Defect 4: File Creation Intent Not Executed via Natural Language Chat
- **Symptom**: When a user asked "Create a Word document explaining SQL basics" or "Create an Excel file containing numbers 1 to 10 and their squares", the system returned text saying a file was created (or a generic message) without actually synthesizing the physical file or presenting a download card.
- **Root Cause**: Although `DeliverableService` has working `generate_docx`, `generate_xlsx`, `generate_pptx`, and `generate_pdf` methods, `chat.py` had no tool execution hook for file generation. Requests stayed in the raw conversational loop.
- **Affected Files**:
  - `backend/app/api/v1/chat.py`
  - `backend/app/services/deliverables/deliverable_service.py`
  - `frontend/src/pages/AiAssistantPage.tsx`

### Defect 5: Exposure of Hackathon Problem Statement Identifiers in User-Facing UI
- **Symptom**: User-facing UI displayed `PS-26117`, `PS 26117`, and competition references:
  1. `AgentsPage.tsx`: Toast messages and buttons named "Dispatch PS-26117 Workflow", "PS-26117 Demo".
  2. `DeliverablesPage.tsx`: Input placeholder containing `PS-26117`.
  3. `Sidebar.tsx`, `DashboardPage.tsx`, `AppRoutes.tsx`: Dedicated "Hackathon Demo" navigation items and tour buttons.
  4. Seed data in `init_db.py` explicitly titled documents and agent templates with "PS-26117".
- **Root Cause**: Hackathon demonstration artifacts from Phase 22 were mounted directly into primary application navigation rather than being restricted to internal developer verification.
- **Affected Files**:
  - `frontend/src/pages/AgentsPage.tsx`
  - `frontend/src/pages/DeliverablesPage.tsx`
  - `frontend/src/pages/DashboardPage.tsx`
  - `frontend/src/components/layout/Sidebar.tsx`
  - `frontend/src/routes/AppRoutes.tsx`
  - `backend/app/db/init_db.py`
  - `backend/app/services/agent/inspection_flow.py`

### Defect 6: Inaccurate Air-Gap Security Badging Under Firebase Auth
- **Symptom**: The UI displayed "True Air-Gapped" or "Air-Gapped Enclave" unconditionally, even when Firebase Google Sign-In was active.
- **Root Cause**: The badges in `AiAssistantPage.tsx` and `DashboardPage.tsx` hardcoded the badge text without evaluating `sovereignMode` or `authMode` from `useAuth()`. Under Firebase mode, external identity network traffic exists, so the UI must state "Local AI Enclave" with clear explanatory notice.
- **Affected Files**:
  - `frontend/src/pages/AiAssistantPage.tsx`
  - `frontend/src/pages/DashboardPage.tsx`
  - `frontend/src/components/layout/Sidebar.tsx`

### Defect 7: Conversation List Pollution in Seed / Test Database
- **Symptom**: The conversation sidebar in `AiAssistantPage.tsx` was flooded with dozens of repeated test conversations created by historical pytest runs ("Auto Select Router Test", "Override Model Test", "Employee Session", etc.).
- **Root Cause**: Pytest tests in `test_phase7_chat.py` created database records on each test invocation without rolling back or purging.
- **Affected Files**:
  - `kelvrin_sovereign.db` (conversations & messages tables)
  - `backend/tests/` (lack of pytest database isolation fixture)

## 3. Targeted Remediation Plan

1. **Model Registry & Single Source of Truth**:
   - Establish stable model IDs (`local-reasoning`, `local-general`, `local-coding`, `local-vision`, `local-embeddings`).
   - Clean out all mock test records from `kelvrin_sovereign.db`.
   - Update `GET /api/v1/models` to filter out test/mock entities unless explicitly in development mode, and deduplicate by stable ID.
   - Update `AiAssistantPage.tsx` and `ModelsPage.tsx` to deduplicate models by stable ID and render a single clean list.

2. **Task Classification & Model Auto-Routing**:
   - Upgrade `TaskClassifier` to return:
     - `task_type`: `GENERAL_QA`, `DOCUMENT_SUMMARY`, `DOCUMENT_QA`, `KNOWLEDGE_SEARCH`, `CODING`, `DATA_ANALYSIS`, `CALCULATION`, `VISION_ANALYSIS`, `OCR`, `FILE_GENERATION`, `AGENT_TASK`.
     - `required_capabilities`: e.g. `["CODING", "TEXT"]`.
     - `requires_document`: boolean.
     - `requires_tool`: boolean.
     - `target_file_type`: `"DOCX" | "XLSX" | "PPTX" | "PDF" | "TXT"`.
   - Implement route enforcement: if user manually overrides to an incompatible model, reject with clear actionable message: `"The selected model does not support this task. Please select a compatible model or use Auto Select."`

3. **High-Quality Actual AI Responses & Local Inference**:
   - Replace static template responses in the local execution provider.
   - For calculations (e.g. `125 * 48`), calculate mathematically.
   - For coding tasks (e.g. factorial function), generate correct, syntax-checked Python implementations.
   - For factual questions (`What is Python?`, `What is a database?`, `Explain photosynthesis.`), generate authentic, thorough educational explanations.
   - For document queries, perform grounded retrieval and synthesize accurate factual citations.
   - When configured local inference (Ollama / vLLM) is available, route directly to local model endpoints.

4. **Natural Language File Generation Tooling**:
   - Detect deliverable requests ("Create a Word document...", "Make an Excel sheet...", "Prepare a PowerPoint...", "Export this as PDF...").
   - Automatically invoke `DeliverableService` with structured content.
   - Physically create verified files on disk with SHA-256 integrity hash.
   - Return structured download links and deliverable cards rendered directly inside the chat message stream.

5. **Eliminate Problem Statement IDs & Remove Hackathon Demo Section**:
   - Remove "Hackathon Demo" navigation items, routes, and dashboard buttons.
   - Replace `PS-26117` in user-facing UI with generic enterprise industrial equipment identifiers (e.g. `PV-201 Pressure Vessel`).

6. **Honest Security Posture Reporting**:
   - Condition all air-gap badges on `AUTH_MODE`:
     - If `AUTH_MODE=local`: Display "Air-Gapped Mode" (100% disconnected).
     - If `AUTH_MODE=firebase`: Display "Local AI Enclave" with the subtitle "AI inference and confidential workspace data remain local. Google/Firebase is used only for authentication."

7. **Database Cleansing & Test Isolation**:
   - Create a test database fixture so future `pytest` executions never pollute `kelvrin_sovereign.db`.
   - Purge duplicate mock conversations and duplicate test models from `kelvrin_sovereign.db`.
   - Seed 4 clean, professional demonstration conversations.
